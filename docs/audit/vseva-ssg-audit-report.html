Production readiness

The app is in a much safer state than at the start of the audit. Every confirmed cross-group data leak is closed on the live database and the live sites. One group of code fixes, plus the Android 1.2 / 1.1 builds, is ready but not yet released.

Residual risk: Medium. Three things keep it above Low. Two library advisories are kept by decision, load testing was skipped, and the public ID card page shows full personal details by choice.

Security

Verified on production

  • All 7 org-data functions on both sites answer 401 without a login. Before the fix they answered 200.
  • A forged push request is rejected.
  • Signed-out database calls to the hardened functions are refused or come back empty.
  • Database functions callable without login, with no caller check: 5, down from 23. Of those 5, 2 check access through a helper, 1 is the accepted ID card and 2 are low risk.

Checked and clean

  • No service keys or push API keys in the shipped app. No source maps, keystores or Firebase files in git.
  • The app's local cache is per user and cleared on logout.
  • Captain-only functions (phone change, leadership, org approval, Super Admin) check role and group.
  • You changed the Supabase public sign-up and leaked-password settings yourself. I didn’t verify them, because they aren’t visible to my tools.

Limits: these are code review and targeted live checks, not a full penetration test. Logged-in access across two real groups was confirmed through your own tests on the device.

Database

This isn't a bottleneck at today's size. The largest table has under 1,000 rows, the indexes the app needs exist, and the slowest app query averages 17 ms. No index changes needed now. Duplicate access rules on a few tables are a clean-up candidate when the data grows.

Fewer server calls

The Dashboard makes one fewer function call per open. The inactivity scan drops from every open to every 6 hours. The notification bell stops its 120 calls an hour while the app is in the background.
